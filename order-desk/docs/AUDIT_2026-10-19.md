## Findings and fixes

1. **Medium workflow/data integrity - oversized conversion.**
   `orders/services.py` copied an unbounded draft into an immutable purchase order,
   although supported detail/export accepts 500 lines. Reproduced 501 matched lines:
   HTTP 201 instead of 409 (red 1 / 20.502s). Shared readiness now exposes `line_limit`
   before payload loading; conversion fetch is bounded 501 with defensive rejection.
   UI explains manual handling. 500 remains ready; 501 produces no order writes and
   retains every editable source line. No truncation/splitting, tenant lock or
   existing conversion-replay weakening. Green conversion/readiness/races22/23.141s;
   final Q/B include the boundary.
2. **Medium privacy - production exception logging.**
   Inherited Django HTTP formatters emitted raw private exception/message/cookie
   markers under actual DEBUG-false production settings (red 1 / 6.618s, all three
   request/security/server paths). `config/logging.py` and production settings now
   emit structured metadata without message interpolation, raw requests, cookies,
   exception text or stack text. Failures retain level/status/method/registered
   route/type/validated request ID. No exception is swallowed. Green 10 / 10.198s,
   including hostile metadata and a non-stringifiable message, plus Q. No actual
   customer leak or exposed live credential was established; no rotation claimed.
3. **Medium correctness - silently invented units.**
   Legacy create serializer/service defaulted an omitted unit to `ea` despite
   the model's blank/unknown default. Three new regressions produced two failures
   (red 3 / 1.633s). Both defaults now preserve blank; explicit units and required
   API quantity remain. No migration or existing-data rewrite. Green 19 / 6.397s
   including related service/read contracts; Q/B actual API/reload. See
   [input preservation](INPUT_PRESERVATION.md).
4. **Measured local performance defect - single-core DB saturation.**
   Three unchanged one-core samples failed twice. Restricted-role EXPLAIN showed
   bounded indexed 50-header page and cached membership subplans (35.861ms), no
   new N+1; DB CPU reached 106.05% of one core, no memory pressure. Changed only
   DB quota 1 to 2 CPUs, same 512 MiB; API unchanged four sync workers/four CPUs/512MiB.
   Both preplanned comparable two-core samples passed; final fresh validation
   follows. No target relaxation, index guess, permission or infrastructure change.

## Threat boundaries, scanners and residual risk

Browser input crosses session/CSRF and workspace authorization before business
parsing. Reviewed accounts views/backends/login limits, organization access and
transaction scope, order/catalogue mutation serializers and organization-first
locks. Login flushes prior sessions, rotates CSRF and expires after eight hours;
logout is CSRF-protected. Native UI uses textContent and memory-only private
state. Context generations and AbortControllers suppress late responses. API
client requests same-origin relative paths with no-store and rejects redirects.
Role restrictions are server-side; native owner tests alone are insufficient.

Database boundaries use parameterized SET LOCAL, idle/autocommit contamination
refusal, fresh membership resolution and forced RLS/composite tenant references.
Conversion, edits and membership services share organization-first locking.
Reviewed bounded reads, immutable conversion snapshots, review/application and
export receipts, and the conversion line-budget inconsistency above. Independent
runtime verifiers and separate-connection races passed on the final candidate.

Upload bytes cross a private storage boundary: actual-byte limits, generated
identifiers, directory-fd O_NOFOLLOW containment, owned 0700 root, regular single-link
0400 files, checksums and OS leases. CSV validation is bounded; PDF signature/EOF
validation is not malware clearance. PDF parsing uses a credential-free child,
memory/CPU/file/process limits, syscall allowlist, bounded pipes and external
15-second deadline. Jobs use attempt ceilings, leases and claim-token publication.
CSV export rejects formulas/control characters without changing machine identifiers.
Unsupported input follows the existing explicit failure/manual-entry workflow.

The proxy terminates local TLS, validates Host, replaces forwarding headers,
denies private paths and uses a script/CSP policy. API/worker run as UID 10001,
read-only roots, dropped capabilities, process/memory limits, private volumes and
separate internal networks. Only proxy ports bind loopback. Logical recovery is
coordinated with stopped writers; encrypted backups and keys are separately mounted,
but remain on this physical host. No public system was tested.
