## Actual attack surface and data flow

The Django resolver inventory contains 67 routes: 23 built-in admin routes, 38
workspace routes and six shell/health/session routes. The machine inventory is
private `audit-2026-10-24/routes.json`; the sanitized full endpoint/method/view
listing is [the route annex](AUDIT_2026-10-24_ROUTES.md). URL declarations are in config/urls.py and
accounts/catalog/orders/organizations/health urls.py. HEAD/OPTIONS follow the
explicit API method lists; unsupported mutations are rejected. No GraphQL,
WebSocket, public file server, customer portal, webhook or ERP integration exists.

Untrusted bytes enter bounded login JSON, catalogue CSV, manual draft fields or
private document intake. Serializers/services validate scalars and tenant relations;
request transactions apply SET LOCAL tenant context under a restricted connection.
PDF bytes are passed to a fixed, credential-free subprocess, not a shell. Linux
seccomp/resource limits and parent deadline constrain its work. Extracted proposals
remain unverified until explicit review/application; exact catalogue suggestions
require acceptance. Conversion freezes an internal snapshot; approval is a separate
recorded transition; CSV generation establishes bytes, not an ERP import.

The native-module frontend uses DOM text rendering and request cancellation with
generation checks. No browser localStorage/sessionStorage, service worker or
third-party analytics were found. Auth uses HttpOnly session cookies and a CSRF
token; private HTTP responses are no-store. Lost mutation responses are reconciled
against persisted receipts. Refresh/back/forward links are hash routes and cannot
authorize an API request. Private originals/exports are outside static storage.

The production-like proxy is the only published service in the normal local
topology (loopback 8080/8443); database/API networks are internal. This audit's
overlay publishes no ports. The proxy replaces forwarded headers; application
proxy trust is explicit. The current login peer budget is shared behind the proxy
(60 attempts/10 minutes, plus 10 per normalized email); a public deployment needs
an approved client-IP/abuse policy, not arbitrary forwarded-header trust.

Run-owned secrets are ignored environment files, isolated CA keys and database
credentials; runtime images do not include these values. Parser children receive
neither credentials nor network/filesystem permissions. Production services do not
call external AI, OCR or ERP systems. The only former browser dependency was Google
Fonts, removed in this audit. Development/operator build and advisory downloads
still require outbound network access. No account-recovery, invitation or MFA
journey is implemented; these cannot be counted as tested capabilities.

## Findings and remediation rationale

1. **Medium: reachable malformed JSON charset returned HTTP 500.** On the old
   DRF 3.18.1 image, a valid-CSRF login with charset rot_13 caused TypeError before
   authentication (safe synthetic marker, no customer input). Regression
   test_non_text_json_charset_is_a_private_client_error_before_auth reproduced
   500 instead of 400; `charset-before.log` preserves the red result. Pin 3.18.3
   and require a private JSON 400 without marker reflection, attempt bucket or
   session creation. Accept-negotiation fixes also arrive; TokenProxy advisory
   does not establish exposure because token authentication is not enabled.
2. **Medium: pypdf resource-exhaustion advisories in 6.20.0.** Lock 6.21.2,
   retaining memory/time/syscall limits and credential isolation. Upstream affected
   ranges establish dependency exposure; no unbounded live exploit was attempted.
3. **Low: remote fonts contradicted production CSP and local privacy policy.**
   Bundle unmodified Outfit/Nunito Sans with SIL OFL texts and provenance, remove
   remote links and use content-hashed relative CSS assets. Require both fonts
   actually loaded in the production browser, not merely present in source.
4. **Verification infrastructure defect: existing proxy ports/default network
   pools prevented fresh isolated gates.** Add explicit unpublished initialization,
   fixed overlay, small run-owned networks and shared prefix for all helpers.
   Preserve unrelated services/volumes and all TLS/security gates. Five script
   regressions cover marker/default/identity/subnets/invalid mode changes.
5. **High product/release gap:** the approved distributor journey is incomplete.
   Existing source ownership requires a PurchaseOrder before document intake.
   Adding nullable ownership alone would bypass existing worker/download/recovery
   assumptions. Follow the roadmap dependency order with composite tenant keys,
   historical provenance and new restricted-role evidence. No commercial rule or
   named ERP compatibility was invented to make the audit pass.
6. **High supply-chain trust exposure: pinned uv 0.12.23.** Upstream reports
   compromised CA intermediates trusted by uv's default bundled root store before
   0.13.4. Upgrade the build/development tool pin to 0.13.5, and Python pins to
   3.14.9, which bundles patched pip/certifi. No new application package is added;
   locked package hashes remain enforced. The runtime venv has no pip/uv and makes
   no external service call, but dependency acquisition was an affected boundary.
   This is a confirmed affected tool version, not proof of MITM or repository
   compromise. The initial 3.14.8/0.12.23 native run was deliberately interrupted
   and its own containers stopped; it is not final release evidence. The final
   full run must use the patched toolchain. Editor environments and independent
   old installations do not upgrade from a manifest change alone.
7. **Medium dependency maintenance: Nginx 1.30.4.** Pin stable 1.30.6 to include
   current memory-safety, TLS-ticket and HTTP/3 fixes. Configuration does not enable
   HTTP/3, AIO/SSI or rewrite into the static alias; no exploitation of those paths
   is established. Fixed-string/variable processing and TLS still warrant the
   maintenance patch. Require the final real proxy TLS/static/Host/browser gates;
   do not count the former proxy build as proof of the new version.
8. **Medium: proxy diagnostics leaked query strings.** A header-only synthetic
   Content-Length above the existing 11 MiB limit correctly returned 413, but
   the standard Nginx error log included PRIVATE-AUDIT-LOG-MARKER from the URI.
   `proxy-log-before.log` retains the bounded reproduction. The proxy now routes
   diagnostics through a supervised allowlist filter that emits only event,
   severity and known failure category. Sanitized access logs retain request ID,
   method, status and elapsed time; Docker provides timestamps. Raw diagnostic
   text (including URI/referrer/file paths) is not emitted. Losing the filter
   stops serving. The redaction test is a required proxy build step and verifies
   malicious-looking lines and live input without EOF. Retest: 413 retained,
   marker absent, request_body_limit/error retained; forced filter exit stops
   proxy with exit 1. Final TERM shutdown exits 143 without SIGKILL and forwards
   graceful QUIT to Nginx. Intermediate tests exposed mawk input buffering and
   inherited upstream SIGQUIT versus shell TERM handling; both were fixed before
   the final image. Full TLS/browser/restart checks still apply to this image.

No schema migration was introduced. A new historical upgrade test migrates the
actual 0008 schema forward with legacy document/review relationships and real
original bytes, verifying unchanged ownership, file key, bytes and blank historical
digest. A blank digest is not silently relabeled as validated content.
