# order-text-pdf-v1

One local, explicitly delimited text purchase-order layout is supported. This
is not a general PDF reader or OCR service. It proposes requested line values
for the existing explicit human review/apply operation.

## Supported layout

US Letter portrait pages, unrotated Courier 10-point text, left origin at 50
points. Text lines descend in visual order without overlapping columns, forms,
images, attachments, scripts or encryption. Each page begins with the exact
anchor `ORDER DESK TEXT PO v1` followed by the exact table heading
`SKU | QUANTITY | UNIT | DESCRIPTION`, and ends with `END PAGE i/n`. Every page
must appear once in physical order and its declared total must match the PDF.
No critical row is skipped. A repeated table heading is allowed between rows.

Rows contain four literal pipe-delimited cells: nonblank SKU (maximum 128), a
positive ASCII decimal quantity (up to 9 integer and 3 fractional digits), an
explicit optional unit (maximum 32), and an optional description. Outer spaces
around delimiters are stripped; raw fragments remain available. Descriptions
may wrap on immediately following lines beginning `> ` on the same page. A
continuation cannot cross a page boundary or start without a preceding row.
Pipes inside fields, missing cells, blank/zero quantities, ambiguous origins,
rotated text, unrecognized prose and truncated/missing footers fail the whole
document. Empty descriptions/units are valid. No prices, totals, currency or
customer headers are inferred or supported in this first profile.

The independently authored synthetic fixture builder emits this layout using
PDF text operators and a standard Courier font. Expected candidates are written
by hand in tests; they are not generated by the extraction algorithm.

## Provenance and completeness

Each field preserves exact interpreted string and raw source fragment, 1-based
page and text-line number, column name, and 0-based exclusive-end `span_start`
and `span_end` character offsets into that page's immutable `result_pages`
text. Description spans can cover continuation lines. These are saved text
offsets, never PDF byte offsets. No word bounding boxes are claimed. The job's
original checksum/profile identity binds the pages and candidates together.
Stable candidate UUIDs derive from job UUID plus page/line identity.

Success is full-document success. An invalid/scanned/mixed/ambiguous page yields
no partial candidates/pages. Failure codes include `unsupported_layout`,
`ambiguous_layout`, `no_text`, `encrypted_pdf`, `malformed_pdf`, `page_limit`,
`text_limit`, `row_limit`, `invalid_sku`, `invalid_quantity`, `invalid_unit`,
`parser_timeout`, `parser_output_limit`, `parser_resource_limit`,
`parser_unavailable` and `source_unavailable`. Human decisions and draft readiness
remain independent of extraction. Unsupported input uses existing manual draft
entry and authorized original-byte download; no OCR fallback is invoked.

## Durable execution and limits

Private verified PDFs share the existing extraction queue, two-minute claim
lease, maximum three attempts, immutable successful results and fresh
membership/source/claim checks. Only transient operational failures
`source_unavailable`, `parser_unavailable`, and `parser_timeout` permit PDF retry.
Permanent input/profile/resource failures cannot be retried through the API.
CSV retry behavior remains compatible. Current source/profile changes select a
new versioned job; historical reviewed results and receipts remain immutable.

One explicit job runs at a time per operator invocation. On the supported
Docker/Linux x86_64/aarch64 runtime, the supervisor runs a fixed Python script
without a shell, with a minimal environment and no inherited database/API
credentials. Verified source bytes enter through stdin. The child closes other
descriptors, sets 256 MiB address space, 10-second CPU, zero file-output size,
32-descriptor and one-process limits, and Linux no-new-privileges/seccomp before
PDF decoding. Seccomp denies network, filesystem opens/mutations, process
creation/execution, tracing and resource-limit relaxation. Parsing is memory
only; no temporary files or scratch volume is provided.

An external supervisor caps wall time at 15 seconds, stdout at 2 MiB and stderr
at 4096 bytes, drains both pipes concurrently and terminates/reaps the process
group on timeout or overflow. Input is at most 10 MiB; at most 10 pages,
64 KiB saved text per page, 256 KiB total text, 4096 characters per field and
500 candidate rows. Library decoding limits supplement OS memory/CPU limits.
Limits fail closed on unsupported OS/architecture. Native Windows parsing is
not supported; Windows development uses the verified Compose Linux worker.
These controls are process isolation and resource bounds, not malware scanning
or proof against all kernel/parser sandbox escapes.

```powershell
docker compose build api
docker compose run --rm extract python manage.py process_document_extraction --workspace <uuid> --actor <uuid> --job <uuid>
```

The existing `process_csv_extraction` command remains a compatible alias for the
shared lifecycle. No broker, automatic discovery or credential-bearing parser
child is introduced. Actual resource/fixture/native/runtime/browser results are
recorded in PROJECT_STATE.md after execution.
